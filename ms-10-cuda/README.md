# Phase 10: CUDA down to the assembly

`ms-10-cuda` · after the common core · 10 sub-modules, 0 written · 0 exercises

CUDA in depth, from indexing to assembly. Each optimization is justified by a micro-benchmark and a measured roofline, then by the SASS that explains the counter. The phase closes on L5, a kernel that beats the reference, and minishell lays the ground for orchestrators.

**Skills this phase builds**

- A roofline measured with self-written micro-benchmarks
- A Nsight Compute counter explained by the assembly
- A kernel that beats the reference, numbers published

| Sub-module | Layer | What it covers | Where the work is |
|---|---|---|---|
| `cu-03-indexing` | added | Work out a thread's global index from its grid and its block, and write a kernel where every thread bounds its access whatever the size of the data | planned, not written yet |
| `cu-04-coalescence` | added | Put a figure on what an uncoalesced memory access costs, all else being equal, and reorder a kernel's accesses until the measurement moves | planned, not written yet |
| `cu-05-tiling` | added | Tile a kernel in shared memory, justify the tile size by the memory available per block, and measure the global memory traffic saved | planned, not written yet |
| `cu-06-reduction` | added | Write a reduction that stays exact whatever the input size, and say at each step how many threads are still working | planned, not written yet |
| `cu-07-occupancy` | added | Compute a kernel's occupancy from its block size, its registers and its shared memory, against the per-SM limits on threads and blocks, and show on a measurement that higher occupancy is not always faster | planned, not written yet |
| `cu-08-nsight-compute` | added | Read an Nsight Compute report and classify a kernel's bottleneck by naming first the precision and the unit that computes: on an H100, going from fp32 on CUDA cores to fp8 on tensor cores multiplies the intensity by 4 but the ridge point by 30, from 20 to 591 FLOP per byte, and a compute-bound kernel can turn memory-bound there | planned, not written yet |
| `cu-09-roofline` | added | Place a kernel on a roofline built from your own micro-benchmarks, and not from the figures the vendor announces | planned, not written yet |
| `cu-10-assembly` | added | Read a kernel's SASS to explain a counter of the Nsight Compute report, and stop at reading | planned, not written yet |
| `l5-01-beat` | proof | Beat the reference, pinned to its version, with a kernel of your own on a precisely bounded case, and ship the bench that verifies it: correct on every shape of the case, cheating and memory regressions caught, gain measured with its standard deviation, replayed and placed on a roofline at the peak of the measured clock, and the cases where it loses said too | planned, not written yet |
| `c-11-minishell` | added | Write a shell that chains fork, exec, pipes and redirections without leaking a descriptor, and whose every error exits with the expected code | 42 subject, not published |
